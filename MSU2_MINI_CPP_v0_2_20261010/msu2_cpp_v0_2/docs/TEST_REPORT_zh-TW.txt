MSU2_MINI C++ v0.2 主代理評估與交付紀錄
日期：2026-10-10 UTC

一、結論

跨幀差異更新核心、CLI 與觀測欄位已實作，可進入 Windows 實物驗證。
主代理審查後接受目前實作：比較基準是最後完整送出的畫面；被取代的等待幀不會推進基準；
一次更新的所有區域完成後才提交基準，任何區域失敗則停止，不繼續使用可能不一致的裝置狀態。
目前測試未發現程式錯誤。這不是已在實物上達到 60 FPS 的結論。

二、本版改變

stream 增加 --update full|diff，預設 full，以保留與 v0.1 的比較方式。
diff 先轉 RGB565 再逐像素比較，評估全幅、變動包圍矩形、合併 8×8 區塊及水平差異段。
候選成本為實際編碼 bytes 加每區域 384 的啟發成本，最多 32 個區域；合併時可能重送未變像素。
384 並非實際送出的 bytes，也不是由裝置延遲擬合的結果，後續可依實物紀錄調整。
--mode pair 的頁內壓縮與跨幀差異更新可以同時使用。
靜態畫面可略過傳輸；略過數獨立列為 unchanged_frames，不當作送出 FPS。
diff 預設每約 1000ms 在下一個處理畫面做全幅刷新；--keyframe-ms 0 可停用，首張仍完整傳送。
新增 diff-bench，及 changed_pixels、transmitted_pixels、rectangles、update_kind 等 CSV 欄位。
沿用原有 LCD 開窗與頁傳輸協議，未加入 Flash 或 MCU 韌體寫入功能。

三、離線資料量證據

來源：docs/diff_benchmark_linux.csv，Linux 已執行，300 張相同來源序列逐一比較。
包括第一張完整畫面；不含週期全幅刷新、USB、來源節拍或等待幀取代。

圖樣與模式        全幅總 bytes    差異總 bytes    減少比例
moving / pair      9,941,472          215,730        97.8300%
moving / raw      11,705,400          389,766        96.6702%
solid/bars/checker      依模式而異，只送首張        99.6667%
gradient/noise          選擇全幅更新                 0.0000%

判讀：局部移動具有明顯資料量優勢；變動分布廣或命令成本偏高時，回退全幅是合理選擇。
靜態圖樣的 99.6667% 是略過 299 張相同來源，並不代表產生 300 次可見更新。
prepare_ms 包含比較、候選規劃及編碼，未暖機且先量 full 再量 diff；只能作初步 CPU 觀察。
資料量減少不能直接換算成實物 FPS 倍數，開窗回應延遲及面板行為仍可能限制效能。

四、已完成的驗證

依使用者要求，測試交由 6.1 Sol / xhigh 子代理執行，主代理負責程式與結果評估。
詳細命令、環境、限制與 binary SHA256 見 tests/TEST_RESULTS_61_XHIGH.txt。

- Release：既有核心 14,883 項斷言、差異核心 3,041,516 項斷言及 POSIX CLI/PTY 模擬通過。
- 最終 ASan/UBSan 核心：既有 14,883、差異 3,078,677 項斷言通過；後者包含最後新增的稀疏超限案例。
  LeakSanitizer 因測試環境相容性停用，未作記憶體洩漏驗證。
- 獨立命令解碼器在保留畫布上重建各次更新，比對完整 RGB565 來源；確認區域外像素不被修改。
- 覆蓋單像素、高低位元組差異、四角、奇數寬、129 像素跨頁、邊界回繞、區域合併、雜訊回退。
- 模擬慢速裝置，確認等待幀被取代後仍與最後完整送出的畫面比較，多區域命令不交錯。
- 強化的途中失敗案例確認：第一區域已完成、第二區域無回覆時停止，整個未完成更新不列入成功 CSV。
- CLI 驗證靜態略過、週期全幅刷新、無效引數、既有 CSV 保護，以及握手失敗不建立新 CSV。
- Windows x64 CLI 與最終差異測試均交叉編譯成功，無編譯警告；Windows 執行檔未在此環境執行。
- CMake 未安裝，CMake/CTest 路徑未執行；Linux 使用 scripts/build.sh 與 tests/run_tests.sh。

五、與先前實物資料的關係

v0.1 使用者回傳紀錄中，moving 目標 30 FPS 的 USB 2.0/3.0 皆產生 300 張、送出 236 張、取代 64 張。
主機送出速度分別為 23.5016 與 23.4637 FPS。USB 3.0 moving 平均 payload_write_ms 約 41.959ms，
轉色與編碼合計約 0.125ms，支持優先減少傳送資料量。單次比較尚不能判定插孔類型的效能差異。
USB 2.0 moving 逐幀 CSV 未補，不以推測補值。本次不再要求該檔案。

六、下一次實物驗證

操作步驟與完整命令見 README_zh-TW.txt。
先測 moving / diff / 30 FPS，再測 60 FPS，使用 --keyframe-ms 0 排除週期全幅刷新的干擾。
保留每次 CSV 與 PowerShell log，確認移動圖案跨過左右邊界時沒有殘影、缺塊或錯位。
需要對照時以同一版 --update full、相同圖樣及節拍再跑一次，每次用新的輸出檔名。
host_send_fps 表示主機傳送完成頻率，並非 LCD 可見 FPS；若要驗證面板刷新需另用影片或適當量測。
多區域更新不具整張原子交換保證；裝置保留區域外像素、待機行為及 Windows 桌面擷取仍待實物確認。
macOS 執行與建置亦未在本次驗證，附的 Linux 執行檔不能在 Mac 上直接使用。

七、套件內容

bin/windows-x64/msu2.exe：Windows x64 執行檔。
bin/linux-x64/msu2：本次 Linux 測試執行檔。
include、src、scripts、CMakeLists.txt：C++17 原始碼與建置入口。
tests：測試原始碼、事實紀錄及 Windows DLL 匯入列表。
docs：協議、基準 CSV、此評估與執行階段授權文件。
examples：沿用 v0.1 的圖樣及離線命令範例，命令格式未改變。
FILE_INDEX.json、CHECKSUMS.sha256：交付內容大小與 SHA256，供核對檔案完整性。
