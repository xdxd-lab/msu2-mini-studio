# 開發交接入口

適用於同機換帳號或新電腦 clone。遠端來源為 [xdxd-lab/msu2-mini-studio](https://github.com/xdxd-lab/msu2-mini-studio)，預設分支 `main`。以實際 commit、工作樹及當次指示為準，不從舊聊天或候選檔名推斷目前狀態。

## 接手順序

1. 閱讀 [AGENTS.md](../AGENTS.md)、[現況與待辦](STATUS_zh-TW.md)、[架構](ARCHITECTURE_zh-TW.md)。確認這次任務、檔案修改者及測試者，避免同時修改同一範圍。
2. 記錄 `git rev-parse HEAD`、`git status --short --branch`、`sw_vers`、`uname -m`、`xcrun clang++ --version`。有未提交修改時，先辨識其擁有者與用途；不要清理未追蹤或被忽略的成果。
3. 依[README](../README.md)使用獨立 `BUILD_DIR` 建置與離線驗證。核對 App 絕對路徑、版本、簽章與 SHA256；不要覆寫別人正在使用的候選，也不要透過名稱搜尋啟動同名舊版。
4. 閱讀對應 CI run 和本機原始證據的限制，向接手者交代哪些是已觀察、哪些只是推論。離線通過不代表硬體或正式發行驗收完成。
5. 依現況文件的優先順序選定下一個可驗證問題。文件中的實驗建議不是硬體執行指令；本次儲存庫整理沒有安排新實機測試。

## 檔案與權限邊界

| Git 提供 | 必須另外交接或重新取得 |
|---|---|
| 程式、測試、建置腳本、合成測試圖、文件 | 本機 `results/` 原始日誌、App、實驗命令與執行檔雜湊 |
| CI 設定與公開 run 的結果 | 實際裝置狀態、序列埠、使用者圖片與素材配置 |
| bundle identifier 及預設 ad-hoc 建置方式 | 螢幕擷取授權、簽章身分與發行憑證 |

需要搬移證據時，只複製指定實驗目錄，保存檔案清單、雜湊及完整性判讀。不能把缺少原始資料的文件摘要當成可重算的量測。來源 commit 也不保證與既有凍結 App 相同。

## 實機工作規則

由指定測試者獨占 MSU2 序列埠；實機前檢查 cu／tty 兩別名及共用 serial guard。不同 clone 的預設鎖目錄可能不同，同機協作時須明確使用相同 `MSU2_SHARED_LOCK_ROOT`。已有擁有者時等待自然結束，不中斷或另開競爭連線。

每次使用凍結執行檔，保留前後 SHA256、設定、命令、退出碼、CSV 及日誌。不要於實驗中重建該 binary。素材 Flash 寫入會改變資料，測試範圍必須包含具體圖片、頁範圍及備份；不以寬鬆 ACK 或增加 timeout 掩蓋失敗。

## 新 clone 如何接手團隊工作

Git 只帶來程式、文件與 CI 設定；團隊的訊息紀錄、`results/` 原始證據、凍結 App 與實驗命令都留在原機器，不在儲存庫內。新 clone 接手時：

1. 依「接手順序」讀文件，並向上一位成員或使用者索取移交內容（見下方範本）及需要的 `results/` 實驗目錄；取得後核對檔案清單與雜湊，缺少原始資料的摘要不當成可重算的量測。
2. 角色以使用者當次指派為準（PM／DEV／QA1／QA2，見 [AGENTS.md](../AGENTS.md)）；不沿用舊的窗格、對話或模型設定，也不假設舊訊息 ID 仍有效。
3. 若團隊使用本機的 `hcmsg`：用 `CBK` 要求完成回報、`ACK` 要求收到回覆，回覆寫 `RE <原ID> <OK|FAIL|BLOCK|ACK>`；任務代號放內容第一個詞。這是團隊的本機工具，不是貢獻者的先決條件，沒有它時以 issue、PR 或當面移交代替。
4. 合併、發布、刪除、對外推送與改設定仍須使用者針對該對象明確同意。

## 每次移交要留下什麼

```text
任務與預期行為：
來源 commit／分支及未提交修改：
檔案修改者／測試者／審核者：
實際 App 路徑、簽章與 SHA256（如適用）：
已完成：變更、驗證命令、退出碼、CI run：
證據：Git 中的摘要；另外保存的本機路徑及完整性：
未完成：具體問題、下一步、停止條件：
當前硬體擁有者與裝置狀態（未檢查就寫未知）：
```

歷史同機換帳號紀錄保存在[歷史區](history/README.md)。其中模型、pane、session、App 路徑及授權狀態只供追溯；不能直接套用到新的工作階段。
