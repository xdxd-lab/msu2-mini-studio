# 經驗整理

更新日期：2026-11-18。整理 11/12 至 11/18 工作中反覆出現、值得下一位接手者先知道的技術經驗。各項結論與證據見[現況](STATUS_zh-TW.md)與[證據索引](EVIDENCE_INDEX_zh-TW.md)。

## 計數與量測口徑

- **主機送出不等於 LCD 更新。** 所有幀數都是主機送出量；面板是否更新、閃爍或保持畫面只能另行目視或量測。
- **正式窗以 `stream_begin` 為原點。** 取 diagnostics 中 session 的 `stream_begin` 時間戳，不用記錄檔開始時間；兩者差幾百毫秒就會讓幀數差一兩幀。
- **CLI 結束時的 `host_fps=0` 是停止後的快照**，不採用。
- **stdout 的 `dropped` 是來源 frame ID 缺口**；`events.log` 的 `waiting_frames_replaced` 是佇列取代次數。數值可能相同，但定義不同，報告時要寫明取自哪一個欄位。
- **stdout 的 `reconnects` 計入同一連線內的 idle renewal**，不等於重新開埠。是否真的重開序列埠，要看 diagnostics 的 connect open／close 次數。
- **鎖檔只記錄 PID 文字，程序結束後檔案仍在。** 檔案存在不代表被占用，以當下 owner 檢查為準。

## 實機執行

- **沙箱 EPERM 與螢幕錄製權限是兩回事。** 受沙箱限制的執行環境可能在開埠時就被拒（`file-write-data`），與產品、TCC 無關；不要用改產品或重新授權來處理。
- **使用不需螢幕擷取的內建來源**（`noise`、`solid`、`bars` 等）可避開權限與桌面內容不固定的問題，但不能代表真實桌面內容，也不能驗證「部分靜止、部分變動」的情境。
- **靜態內容不一定啟用 center3。** center3 依預測成本啟用；要觀察分區行為，需確認 diagnostics 的 trigger 欄位確實出現啟用事件，否則該輪等同 priority off。
- **一輪只是一個樣本。** 單次結果寫成「本輪觀察」，未觸發的程式路徑（例如側區截止期限）不能因整輪成功就視為已驗證。

## 離線測試

- **斷言失敗時要先放行所有 gate。** 用 gate 卡住假傳輸或 lease 的測試，若斷言丟出例外時 gate 仍關著，解構會一直等待，最後變成逾時而不是乾淨的 FAIL。以 RAII 物件在例外路徑放行。
- **用突變對照證明測試有判別力。** 在副本中拿掉被測的判斷條件，確認測試會失敗；突變只在副本進行，不改產品原始碼。
- **watchdog 只傳白名單環境變數時，控制旗標也要列入白名單**，否則旗標悄悄失效，整組測試意外重跑。
- **路徑含空白時，用陣列傳參數。** 把旗標存成字串再展開，`-I` 路徑會被拆開；私有標頭若只在原始碼目錄，複製出去的副本也找不到它。
- **bash 函式內的 `local` 是動態作用域。** 被呼叫的函式若用同名迴圈變數，會改掉呼叫者的 `local`；輔助函式使用不同變數名稱，或在 subshell 中執行。

## 工具與流程

- **在大型二進位檔中搜尋時，不要用帶前後文的正規表示式**（例如 `.{0,200}關鍵字.{0,200}`），它會在每個位置嘗試比對而極慢；先用固定字串取得位移（`grep -abo`），再擷取附近內容。
- **CI 狀態 UNSTABLE 不一定是測試失敗。** 例如 runner 沒接單、0 步驟就被取消；合併前要看實際 run 內容，並由有權者明確接受，不以重跑舊 run 掩蓋。
- **證據副本提交後不改寫。** 更正以新增附記或新日期目錄處理；去識別化時逐檔記錄原件與輸出的 SHA256，並另做殘留敏感資訊掃描。
- **公開文件只寫相對位置與摘要。** 不放本機絕對路徑、帳號、序列埠序號、程序 ID、原始 RX 內容或其他應用程式的視窗資訊；實驗子目錄名稱若含程序 ID，只寫上層目錄。
