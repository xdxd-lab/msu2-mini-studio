# 儲存庫工作流程與交接

Git 保存可重建的產品原始碼、測試、腳本、合成測試圖及文字文件。`results/`、`dist/`、App、建置物件、下載的參考 PDF、外部歷史量測檔及生成的設計圖維持本機保存，不隨原始碼提交。忽略檔案不等於可刪除檔案；本機研究及測試原始資料仍應保留。

## 日常修改

1. 閱讀根目錄 `AGENTS.md` 及使用者當次分工，盤點目前 Git 與其他代理工作。
2. 讓一個修改者擁有明確的檔案範圍，先理解狀態、擁有權及錯誤處理，再做可驗證的小改動。註解著重原因、限制與不變條件。
3. 使用獨立 `BUILD_DIR` 進行離線測試與乾淨建置；涉及記憶體／執行緒生命週期時跑 ASan／UBSan。以實際退出碼與診斷輸出判定，不用擴大 timeout 掩蓋失敗。
4. 提交前檢查 `git diff --cached --check`、變更範圍、敏感內容、二進位及忽略規則，再檢查選定提交內容在獨立目錄能重建。不要直接 `git add .` 後推送。
5. commit 描述問題與最後行為，驗證說明列工具鏈、通過項目和未測限制。已凍結供實機的 App 必須另外保存，不隨 refactor 重建。

同機可以直接閱讀儲存庫與[交接入口](../handoff/README_交接入口_20261105.md)；換機先 clone、再依 README 建置，不能假定本機候選、絕對路徑、序列埠、憑證或螢幕授權存在。歷史 pane／session ID 只作辨識，當前角色與授權以使用者最新指示為準。若要搬移原始實驗證據，另行選取與校驗，不把整個結果目錄當作一般原始碼推送。
