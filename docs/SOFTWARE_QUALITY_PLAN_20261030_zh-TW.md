## 第二階段：桌面效率與現有疑點

1. **Pair 逾時分類**：補低干擾診斷，分清握手、window ACK、payload 寫入與來源失敗。先建立 trace 的離線測試與資訊邊界，再做短 Raw／Pair 實機對照。不得放寬 ACK 或 timeout 掩蓋錯誤。
2. **桌面時效**：補擷取序號／時間、影格年齡、排隊等待、視窗數與區域過期時間。效能報告同時列來源取得率、處理率、主機更新率、各區時效及傳輸量；LCD 實際更新率需獨立量測。
3. **分區公平性**：既有 center3/60 左區飢餓已有證據。先用離線情境約束最久過期時間，再比較單一策略變更；不能只以總更新次數增加作為成功標準。
4. **長期可靠度**：短測與錯誤分類通過後，再進行反覆啟停、背景／閒置恢復及長時間執行；追蹤常駐記憶體、執行緒數與錯誤累積。
5. **發行流程**：固定 App 路徑、可追溯版本及穩定簽章身分，另行驗證升版後權限。沒有有效簽章憑證時，不能宣稱授權能跨重建保留。

## 本輪已核准實作

| 問題與程式機制 | 修正邊界 | 對照方式 |
|---|---|---|
| 原子旗標在 condition variable 所用 mutex 外改寫，仍可能於 predicate 檢查與等待之間漏掉通知 | 停止、中斷與解構先持同一把鎖改旗標，解鎖後通知；不改傳輸協定 | 建構／解構及連線／中斷壓力回歸；機率性競態不保證在舊版重現 |
| full、bounding、tiles、runs 可能具有相同矩形序列，卻反覆配置、裁切及編碼 | 固定容量的幾何紀錄跳過重複候選，全幅直接使用原像素；保留所有選擇規則 | 舊版與候選版的計畫、矩形順序、metadata、window 和 payload 逐 byte 比對；量測時間及 C++ 配置量 |
| 閒置重握手在每幀恢復處理外丟出例外，繞過 auto_reconnect | 尊重使用者已選的 auto_reconnect；握手失敗獨立紀錄，重新連線後丟棄舊擷取幀並完整更新 | 舊版預期失敗、候選版通過；關閉 auto_reconnect 時仍停止，不重複歸類為 ACK 失敗 |
| 重試計數在整段串流持續累積，已恢復的故障也會耗盡三次上限 | 只有成功傳完一個邏輯更新才重置；握手成功、略過及未變動都不重置 | 四次分開且有成功更新隔開的故障能恢復；連續失敗仍受原三次上限約束 |

註解集中在上述不變條件與原因。效能改動沒有改變顯示策略；修正後執行速度改變仍可能影響依耗時決策的自動分區觸發時刻，實機排程效果需另行量測。

## 結果解讀

- 微基準的編碼時間下降不等於 USB 或 LCD FPS 同比例提升。
- ASan／UBSan 通過只覆蓋實際執行的路徑，不代表已證明沒有競態或硬體時序錯誤。
- 既有 `docs/NEXT_VALIDATION_20261024_zh-TW.md` 的問題清單仍有效；其中模型分工由本文件的本次例外覆蓋。
- 未找到可用的 MCU 韌體 binary，不能把韌體 ACK 時序或反組譯假說寫成已證實事實。
