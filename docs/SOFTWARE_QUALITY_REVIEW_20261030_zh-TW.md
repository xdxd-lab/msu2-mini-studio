# 軟體最佳化第一批審核結果

2026-10-30；p1 Codex 統籌與審核，p2 GPT-6.1 Terra／中執行測試，p3 Claude Opus 分析、實作及複核。四項產品修正已完成，通過凍結來源的離線驗證。這是第一批工程改善，尚未完成實機、長時間記憶體及發行驗收。

## 實際變更

| 位置 | 改善與原因 |
|---|---|
| `msu2_macos_app/src/controller.cpp` | 停止、中斷與解構時，在 condition variable 使用的同一把 mutex 內更新旗標，解鎖後通知；避免僅依賴 atomic 而可能漏掉喚醒。註解說明檢查條件與進入等待之間的競態。 |
| 同上 | 閒置握手失敗現在遵守已選用的 `auto_reconnect`，另寫 `idle_renewal_failure` CSV；不重複算成 ACK 或傳輸失敗。成功重連後清除舊參考畫面並完整更新，過期的已排隊影格由時間門檻排除。成功握手等待時間不再計入編碼耗時。 |
| 同上 | 每次成功傳完一個邏輯更新後才重置重試計數，避免四次各自恢復成功的故障耗盡整段串流的額度。持續失敗仍受三次上限約束。 |
| `msu2_linux_v0_3/src/delta.cpp` | 固定容量的幾何紀錄跳過相同矩形序列的重複編碼；全幅直接使用輸入像素，省掉裁切複製。保留候選順序、計分、參考影格及所有協定位元組。 |
| `msu2_macos_app/tests/test_controller_edges.cpp` | 增加閒置恢復、停用恢復、四次分開故障，以及各 100 次建構／解構與連線／中斷回歸。檢查錯誤分類、連線持有權、恢復後第一個完整視窗及 22 欄 CSV。 |
| `msu2_macos_app/scripts/test.sh` | 增加 `SANITIZERS=1`，在編譯及連結加入 ASan／UBSan，並以 `-fno-sanitize-recover=all` 使診斷造成失敗。預設建置行為不變。 |
| `msu2_linux_v0_3/tests/benchmark_delta.cpp`、`run_delta_benchmark.py` | 固定語料、完整計畫序列化與逐 byte 比對；分開量測規劃時間與 C++ 配置量，保留工具鏈、來源／執行檔雜湊、命令及退出碼。 |

沒有修改 UI、螢幕權限或 ACK 接受規則。顯示策略本身未改，但運算耗時改變仍可能影響自動分區依時間作出的決策；此效果尚未實機量測。

## 審核結論與後續

接受本批產品修正及測試工具，狀態為「離線驗證通過」。p3 的原始分析保存在 `results/macos/software_quality_20261030/opus_review_terminal.txt`，本文件修正了把規劃經過時間稱為 CPU time 的措辭。

本輪沒有操作 MSU2 USB、寫入 Flash、開啟 GUI、重設 TCC，也沒有量測實際桌面或 LCD FPS。微基準只省下每次規劃約數十至百餘微秒，不能據此推算 25 FPS 會提高多少。Pair 實機逾時仍未定位，分區飢餓仍待另案修正。恢復後首窗全幅有測試；丟棄舊幀的時間門檻已審閱，但尚無專門斷言驗證幀的新鮮度。

後續順序見 [品質計畫](SOFTWARE_QUALITY_PLAN_20261030_zh-TW.md)：先補 Pair 診斷與桌面時效指標，再做受控實機對照、分區公平性、長時間 RSS／資源測量及升版授權驗收。獨立 CMake／CTest 路徑因環境未安裝 cmake 沒有執行；核心測試已由 macOS 腳本編譯並執行。
