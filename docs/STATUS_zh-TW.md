11/17 兩輪的共同限制：沒有前景守門，桌面內容未固定；螢幕錄製權限沿用先前狀態，未另行記錄；CLI 結束時印出的 `host_fps=0` 是停止後的快照，不採用；序列埠鎖（flock）的執行中狀態未保存，只有前後 owner 檢查。stdout 的 `dropped` 是來源 frame ID 缺口（見 `controller.hpp` 的 `Snapshot`），與佇列取代定義不同，即使數值相同也不混用。

11/18 的 05 第一次嘗試在受沙箱限制的執行環境中開埠即被系統拒絕（EPERM），沒有送出任何幀；在允許存取裝置的環境重跑才得到上表結果。這是執行環境限制，與產品或螢幕錄製權限無關。11/16 曾以外部瀏覽器視窗作為受控畫面，因視窗幾何不穩定而在開埠前停止，之後改用內建來源。
