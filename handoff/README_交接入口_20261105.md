## 下一步與限制

1. 問清楚使用者切換帳號後希望接續什麼；先檢查其他代理工作、目前裝置及程式狀態。不要因本交接直接啟動硬體。
2. 若繼續找斷線原因，可考慮由指定測試代理在失敗後、未拔插時做一次只連線／斷線的握手探測；並以相同內容、較低目標幀率的 Pair（例如 24）對照既有 Raw，分離編碼與速率因素。這是建議，尚未執行；確保使用者指示、實際權限與自動審查允許，失敗即保留證據，不得繞過拒絕或無限重試。
3. 一次只能一個擁有者：每次實機前檢查 `/dev/cu.*` 和 `/dev/tty.*` 對應別名的擁有者及共用 serial guard；專案鎖預設 `results/macos/.device-locks/`。若有擁有者，等其自然結束，勿中斷。每次凍結執行檔、保留前後 SHA256、命令／操作、退出碼、CSV／events／diagnostics、實際時長與設定；執行時禁止重建或覆蓋該 binary。
4. 診斷以 `MSU2_DIAGNOSTICS=1` 為主、只在必要時用較高記錄量；必須確認進程環境與日誌確實生效。檢查 `log,end`、lost 和 write_failed。畫面來源需是真實桌面，不得以合成圖冒稱。不要保存螢幕畫面或未知原始 payload，除非使用者另行明確指定。
5. 不要放寬 ACK 規則或 timeout 來掩蓋失敗，不要修改既有顯示更新演算法以便做診斷。Pair ACK prefix 不代表 LCD 完成顯示。
6. 一次額外重跑 Raw 曾被自動審查拒絕，理由為既定矩陣外再次傳送桌面資料；已有 Raw 回合，不要繞過拒絕。若未來確實需要額外回合，清楚說明具體理由與當前審查要求。
